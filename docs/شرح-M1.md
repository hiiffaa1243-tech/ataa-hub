# شرح المرحلة M1 — الأساس على ERPNext v16

هذه المرحلة تبني الأرضية التي تقف عليها كل المراحل التالية: تطبيقنا `ataa_hub` صار يُثبَّت **بجانب ERPNext**، ويضيف حقوله وإعداداته وحساباته دون أن نلمس كود ERPNext أو Frappe.

> نسخة v1 القديمة (تطبيق Frappe مستقل) محفوظة في Git بالوسم `v1-frappe`. الأجزاء التي تعتمد على الجداول القديمة (مشروع التبرع، المتبرع، التبرع، طلب الصرف، الـ API، ميسّر) حُذفت مؤقتاً، وتُعاد كتابتها على ERPNext في M2–M4.

---

## الملفات وشرح كل واحد

### `ataa_hub/hooks.py` — لوحة التحكم في التطبيق
يخبر Frappe عن تطبيقنا:
- `required_apps = ["frappe", "erpnext"]`: لا يُثبَّت إلا مع ERPNext.
- `fixtures`: قائمة التخصيصات التي تُصدَّر مع التطبيق (الحقول المخصصة، الأدوار). عند تثبيت التطبيق على أي موقع جديد تُنشأ تلقائياً.
- `after_install` و`after_migrate`: دوال تعمل بعد التثبيت وبعد كل تحديث، لتجهيز الحسابات والإعدادات.
- `before_tests`: تجهّز موقع الاختبار (شركة سعودية بالريال) قبل تشغيل الاختبارات.
- `doc_events` على **Company**: عندما تُنشأ شركة جديدة (مثلاً من معالج الإعداد) نجهّز لها حساباتنا مباشرة.

### `ataa_hub/constants.py` — الأسماء الثابتة
كل اسم يُكتب مرة واحدة هنا: الأدوار، أنواع الصناديق (مقيّد/غير مقيّد)، القنوات، أسماء الحسابات، طرق الدفع، مستويات العضوية ومبالغها (برونزي 50، فضي 100، ذهبي 250، بلاتيني 500). أي تغيير يتم في مكان واحد.

### `ataa_hub/fixtures/custom_field.json` — الحقول المضافة على جداول ERPNext
32 حقلاً، أهمها:
- **Project** (المشروع): تبويب "التبرعات" فيه رمز المشروع، نوع الصندوق، المبلغ المستهدف، الصورة والعنوان العام، وحدة الأثر، والمبالغ الجاهزة.
- **Customer** (العميل = المتبرع): تبويب "المتبرع" فيه الجوال، إجمالي العطاء، مستوى العضوية وحالتها وتاريخها. كلها للقراءة فقط، يحدّثها النظام لا المستخدم.
- **Sales Invoice** و**Payment Entry**: علامة "عضوية" لتمييز فواتير ومدفوعات العضويات.
- **Journal Entry** (القيد): "أُنشئ من" ليربط القيد بالتبرع أو طلب الصرف الذي أنشأه.

### `ataa_hub/fixtures/role.json` — الأدوار
المدير التنفيذي، مدير المشروع، محاسب التبرعات، وعميل الـ API (بدون دخول للوحة التحكم).

### جداول جديدة في `ataa_hub/ataa_hub/doctype/`
| الجدول | وظيفته |
|---|---|
| **Ataa Settings** (إعدادات عطاء) | صفحة واحدة: الشركة، المشروع العام، حسابات الإيرادات والمصروفات والتحويل، وطريقة الدفع لكل قناة. تُعبّأ تلقائياً |
| **Membership Settings** (إعدادات العضويات) | المستويات ومبالغها، أيام إعادة المحاولة (3 ثم 7)، حد العضوية الشرفية، وقالب الضريبة. عند تغيير مبلغ مستوى تتحدث خطة الاشتراك تلقائياً |
| **Membership Tier** | سطر لكل مستوى داخل إعدادات العضويات، مربوط بالصنف وخطة الاشتراك |
| **Project Donation Option** | المبالغ الجاهزة لكل مشروع (مثل "سقيا 100 معتمر = 100 ريال") |
| **Donation API Client** و**API Client Project** | من v1، وصارت قائمة المشاريع المسموحة تربط بمشروع ERPNext مباشرة |
| **Moyasar Settings** | من v1 كما هي: مفاتيح ميسّر التجريبية (السري منها مخفي) |

### `ataa_hub/setup/company.py` — تجهيز الشركة
يعمل بعد التثبيت وبعد كل تحديث، ولا ينشئ شيئاً مرتين:
1. **الحسابات**: إيرادات تبرعات مقيّدة/غير مقيّدة، إيرادات العضويات، تحويلات الصناديق (داخل/خارج)، مصروفات البرامج، وحسابات وسيطة لميسّر والمتجر ونقاط البيع، والبنك الرئيسي.
2. **طرق الدفع**: ميسّر أونلاين، المتجر الإلكتروني، مدى نقاط البيع، تحويل بنكي، شريك. كل واحدة مربوطة بحسابها.
3. **المجموعات**: مجموعة عملاء "Donors"، ومجموعة أصناف "Memberships".
4. **المشروع العام GENERAL**: صندوق غير مقيّد.
5. **العضويات**: صنف وخطة اشتراك شهرية لكل مستوى.
6. يعبّئ الإعدادات الفارغة فقط، ولا يغيّر شيئاً عدّله المستخدم.

### `ataa_hub/setup/install.py` و`setup/wizard.py`
- `install.py`: يستدعي تجهيز الشركة بعد التثبيت والتحديث وقبل الاختبارات.
- `wizard.py`: يُكمل معالج إعداد ERPNext بدون متصفح، بشركة وهمية "جمعية عطاء التجريبية" بالريال وتوقيت الرياض. يُستخدم في Docker والاختبارات.

### `ataa_hub/accounting.py` — رصيد المشروع من دفتر الأستاذ
أهم ملف في هذه المرحلة. الرصيد **لا يُخزَّن أبداً**، بل يُحسب كل مرة من قيود دفتر الأستاذ (GL Entry):
- **الرصيد** = مجموع (الدائن − المدين) على حسابات الإيرادات والمصروفات المربوطة بالمشروع، مع استبعاد القيود الملغاة.
- **إيراد التبرعات** = نفس الحساب لكن على حسابي التبرعات فقط (لشريط التقدم).
- **المحجوز** = طلبات صرف معتمدة لم تُدفع بعد (يعمل من M4).
- **المتاح** = الرصيد − المحجوز.
- **نسبة الإنجاز** = إيراد التبرعات ÷ المبلغ المستهدف.

بهذا لا يمكن أن يختلف الرصيد في لوحة التحكم أو الـ API أو بوابة المتبرع عن الدفاتر المحاسبية.

### `ataa_hub/tests/` — الاختبارات (19 اختباراً، كلها ناجحة)
- `test_setup.py`: الحقول والأدوار موجودة، الحسابات صحيحة النوع، طرق الدفع مربوطة، المشروع العام غير مقيّد، لكل مستوى صنف وخطة شهرية، تغيير المبلغ يحدّث الخطة، وتشغيل التجهيز مرتين لا يكرر شيئاً.
- `test_accounting.py`: مشروع جديد رصيده صفر، التبرع يرفع الرصيد والنسبة، الصرف يخفض الرصيد لا النسبة، القيد الملغى لا يُحسب، المشاريع لا تختلط، تحويل بين بنكين لا يُحسب إيراداً، والتحويل من الصندوق العام ينقل الرصيد دون أن يُحسب تبرعاً.
- `factories.py`: أدوات صغيرة لإنشاء مشاريع وقيود وهمية للاختبار.

- `.github/workflows/ci.yml`: GitHub يشغّل الفحص والاختبارات على v16 مع كل رفع.
